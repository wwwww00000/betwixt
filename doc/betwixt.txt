INTRODUCTION                                                          *betwixt*

Betwixt projects review comments from a repository-co-located plain-text
sidecar into a normal source buffer. Comments begin as virtual highlighted
lines and can be materialized as source-language comment sections for direct
editing. |:write| separates source and review lines and writes each backing
file. The source is passed through Neovim's native write path without the
review lines, so normal write hooks continue to see ordinary source text.

===============================================================================
SETUP                                                          *betwixt-setup*

>lua
    require("betwixt").setup({
      author = "reviewer",
      mappings = {
        comment = "<leader>rc",
        edit = "<leader>re",
      },
    })
<

`author` is used for newly created comments. It falls back to
`g:betwixt_author`, then `human`.

`mappings.comment` creates a comment on the current line in Normal mode or the
selected lines in Visual mode after a sidecar is attached. `mappings.edit`
toggles virtual and materialized display. Set either value to `false` to
disable that mapping. Both comment mappings also work in interleaved mode.

For bindings that work before attachment, add these after setup (with Betwixt
loaded). If using lazy.nvim, use the README's `keys` entries to load on demand:
>lua
    vim.keymap.set("n", "<leader>rc", "<cmd>BetwixtComment<cr>",
      { desc = "Comment on current line" })
    vim.keymap.set("x", "<leader>rc", ":BetwixtComment<cr>",
      { desc = "Comment on selection" })
    vim.keymap.set("n", "<leader>rr", "<cmd>BetwixtReload<cr>",
      { desc = "Reload or attach review" })
<
The Visual mapping uses `:` so the selected range reaches the command.
Keep the global comment mappings and `mappings.comment` consistent if changing
or disabling the key. `<leader>re` remains the buffer-local edit toggle after
attachment. `<leader>rr` discovers an existing default sidecar or reloads the
attached review. It does not discard pending edits; write first, or explicitly
use |:BetwixtReload| with [!] to discard unsaved interleaved changes.

Use normal Visual-line deletion (V, select the whole block, d) and |:write| to
remove a thread. There is no separate delete binding.

COMMANDS                                                    *betwixt-commands*

                                                   *:BetwixtAttach*
:BetwixtAttach[!] [sidecar]
        Attach {sidecar} to the current normal source buffer. Comments are
        placed after their resolved ranges by default; [!] places them before.
        With no path, discover the default sidecar for the current source.

                                                     *:BetwixtOpen*
:BetwixtOpen[!] {sidecar}
        Open the older all-in-one editable projection. [!] places comments
        before their ranges.

                                                  *:BetwixtComment*
:[range]BetwixtComment [type]
        Create an open comment on [range]. Without an explicit range, target
        the cursor line. [type] defaults to `comment`. If no sidecar is
        attached to a saved normal file, lazily create an in-memory review for
        `.betwixt/<source-relative-path>.betwixt.md`; the file appears on the
        first |:write|.
        An existing default sidecar is discovered and attached. The new body
        is materialized for immediate editing. This also works in editing mode;
        range endpoints must be source lines. Existing pending edits survive.

                                                    *:BetwixtReply*
:BetwixtReply
        Append an attributed reply to the nearest projected comment and
        materialize its empty body for immediate editing. Replies inherit the
        root comment's anchor and status. Start from virtual mode: write any
        pending edits and use |:BetwixtVirtual| before replying.

                                                  *:BetwixtRefresh*
                                                   *:BetwixtReload*
:BetwixtRefresh[!]
:BetwixtReload[!]
        Reload the attached sidecar into virtual display, or attach the default
        sidecar if present. Without an attachment or default sidecar, do nothing.
        Unsaved interleaved edits require a write first, or [!] to discard them.

The following commands are local to an attached source buffer:

                                                     *:BetwixtEdit*
:BetwixtEdit
        Materialize review sections using the filetype's comment syntax.

                                                   *:BetwixtToggle*
:BetwixtToggle
        Toggle virtual and materialized display.

                                                  *:BetwixtVirtual*
:BetwixtVirtual[!]
        Return to virtual display. Refuse unsaved materialized edits unless
        [!] is supplied; [!] discards them.

                                                   *:BetwixtDetach*
:BetwixtDetach
        Remove the projection and buffer-local commands and mappings.

SIDECARS                                                    *betwixt-sidecars*

The current sidecar contains one `file:` field and zero or more `## Comment`
sections. Each comment records `range`, `author`, `status`, `type`, an exact
indented `anchor`, optional indented `context-before` and `context-after`, and
a verbatim `body`. New comments capture one immediately adjacent context line
on each side. An empty context block records a file boundary.

A comment may contain ordered `### Reply` sections after its body. Each reply
contains an `author` and `body`. Replies are linear rather than nested and do
not carry their own anchor, status, type, ID, or timestamp. Adding a reply does
not change the root status.

Default sidecars mirror source paths under `.betwixt/` beside the nearest
worktree’s `.git` (directory or file), or under cwd outside Git. Sources outside
cwd and outside Git use `.betwixt/_external/<absolute-source-path>.betwixt.md`.
For example, `src/app.lua` uses `.betwixt/src/app.lua.betwixt.md` with
`file: ../../src/app.lua`. A root-level `sample.lua` uses
`.betwixt/sample.lua.betwixt.md` with `file: ../sample.lua`.
The `file:` field is relative to the sidecar's directory. Existing adjacent
sidecars remain usable by explicit path; they are not automatically migrated.

To delete a thread, delete its complete materialized block, including header,
footer, replies, and paired delimiters, then |:write|. Partial boundary deletion
is rejected. Clearing only the body retains an empty comment. Before writing,
|:BetwixtVirtual| with [!] cancels the deletion and all other pending
interleaved edits. Deleting the final thread leaves an empty, reusable sidecar.

Betwixt uses context only to disambiguate repeated exact anchors. A unique
exact anchor still resolves if its context changed. Betwixt reports a unique
relocated anchor as moved, an edited or deleted target as stale, and repeated
anchors without one contextual match as ambiguous. Older exact-only sidecars
remain valid. Betwixt does not automatically rewrite stored ranges, anchors,
or context.

Comments whose root status is not `resolved` use the amber comment highlight.
A root status of `resolved` uses a muted gray highlight for the complete
comment and its replies.

===============================================================================
USAGE RECIPES                                                *betwixt-usage*

REGULAR BUFFER

Open a saved source file. Run |:BetwixtComment| on the cursor line or a visual
range; the first |:write| creates `.betwixt/<source-relative-path>.betwixt.md`. Use
|:BetwixtEdit| to materialize existing comments, |:BetwixtReply| to append a
reply, and |:BetwixtVirtual| to return to virtual display. Reopen an existing
review with:
>
    :BetwixtAttach
<

AGENT HANDOFF

The sidecar is the shared human-agent conversation; materialized review lines
are only a temporary Neovim editing projection. Before an external agent edits
the sidecar, use |:write| and |:BetwixtVirtual|. The agent appends a root
comment or linear `### Reply` directly to the plain-text sidecar. There is no
standalone agent-facing reply command or CLI. After the external edit, use
|:BetwixtRefresh|.

Do not leave pending interleaved edits across this handoff. If the sidecar
changes externally while the buffer remains interleaved, Betwixt rejects the
next write rather than overwrite the external contribution.

CODEDIFF

Open the saved working-tree file in its normal buffer and create or attach its
Betwixt review. Return to virtual mode, then compare the current file with a
revision:
>
    :CodeDiff file HEAD~1
<
Use the normal Betwixt commands in CodeDiff's editable working-file pane. In
side-by-side mode a uniquely resolved anchor receives an equal-height spacer
on the opposite side. Stale or ambiguous anchors do not receive a speculative
spacer. CodeDiff's `t` mapping toggles side-by-side and inline layouts.

===============================================================================
FILETYPES                                                *betwixt-filetypes*

Materialized editing requires a usable `commentstring`. Prefix-only forms add
the prefix to every projected line. Paired forms put their opening and closing
tokens on separate protected lines outside the aligned Betwixt frame; its
header, body, replies, and footer remain prefix-free.

The automated suite covers Lua (`-- %s`) end to end, JavaScript (`// %s`) for
materialized editing and separated writes, Python (`# %s`) for lazy first
comments and materialized editing, and Markdown (`<!-- %s -->`) for comment
and reply creation, paired materialization, delimiter safety, and separated
writes. Paired review text may not contain either comment delimiter. In
Markdown fenced code blocks the HTML-comment frame is literal code and may be
visible in a live preview even though it is removed from the written source.
